Private by design

Reads only meta/*.json(l) and the file listing. It never opens episodes or video, and uploads nothing.

Same checks as the website

28 checks against GR00T's loader, openpi's loading rules, and 8 checks on whether the data fits π0.5.

The same report every time

A short summary in English: ✅ / 🟡 / ❌ per area and the next step. Say yes for every check and the fixes in order.

Install

Three ways to run it

Claude Code

Unzip into your skills folder, then start a new session.

unzip robot-data-smog-check.zip -d ~/.claude/skills/

You get ~/.claude/skills/robot-data-smog-check/.

claude.ai

Upload the zip as a skill in Settings, then ask in a chat that has your dataset's meta/ files.

No agent

Run the script yourself. It prints the same report.

python3 robot-data-smog-check/scripts/smog_check.py check <dataset-folder>

Add --details for every check.

Ask it

Things to say to Claude

  • Is ~/data/pick_cube ready to fine-tune GR00T?
  • Can I train π0.5 on this dataset? What do I need to change?
  • Check every dataset under ~/recordings/.
  • We're delivering this dataset to a customer. Write a conformance manifest.
Beyond the website

What it can do with the files in front of it

Drafts GR00T's modality.json

From the dimension names: which numbers are the arm and which the gripper. It is saved beside the data for you to confirm, never written into meta/ on its own.

Plans the π0.5 config

Which camera goes in which image slot, the state and action keys, action_horizon, and the norm-stats command, in pi05_config_plan.md.

Seals a delivery

A producer writes conformance.json; the buyer runs verify to confirm what arrived is what was checked, without either side uploading data.

What it doesn't tell you

These are static checks on metadata. Passing means the loader can read the files and the data's shape fits the model, not that a model will train well on it. It doesn't look inside episodes, so frame timing and data quality are out of scope.
